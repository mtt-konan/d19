# Q2b Fixed-Coordinate Audit

## Outcome

`q2b_coordinate_audit_boundary`

This is a data-boundary certificate, not a final Goal blocker. The current
repository does not contain a certified fixed absolute-field power-basis
payload for the sixteen ambient S-unit lifts. Consequently neither the full
`M_const` nor the full `M_norm` matrix, and neither global S-unit lift of the
two Q2a classes, is currently established.

## What Is Stored

The segmented Python snapshot stores the sixteen labels

```text
zeta4, epsilon_1,...,epsilon_5, S_prime_1,...,S_prime_10
```

and stores six unit-generator coordinate tuples plus ten support-generator
coordinate tuples. Those tuples are explicitly tagged
`sage_maximal_order_basis_coordinates`; they are not certified power-basis
coordinates. The snapshot has no multiplication table, change-of-basis map,
or fixed embedding of `K=Q(i)` into the absolute field.

`berry_sextic_magma_sunits.m` is an emitter: it prints
`Eltseq(La!sunit_map(...))` in Magma's absolute-field basis when executed, but
the emitted sixteen vectors are not stored in the repository. The rebuild
source also states that no Magma map or support-generator object is persisted.
The `s_unit_group` record therefore contains labels and the torsion relation,
not sixteen usable field-element lifts.

## Exact Consequences

The current data do prove the ambient dimension `16`, the support slots, the
single torsion relation, and the known constant class

```text
[i] = [zeta4] = (1,0,...,0)
```

At the ideal-valuation level only, the conservative support metadata forces
the following parity skeleton, if `S_prime_j` denotes the principal
generator of slot `j`:

```text
[1+i]       : no odd support slot,
[94*i-169]  : S_prime_3 + S_prime_4 + S_prime_6,
[-94*i-169] : S_prime_7 + S_prime_8 + S_prime_9 + S_prime_10.
```

Each line is still undetermined by an arbitrary global-unit correction in the
six unit coordinates. Thus these are not rows of `M_const`.

Likewise the residue-degree data determine only the prime part of a support
generator norm:

```text
N(S_prime_1),N(S_prime_2)       = [1+i] * [i]^u,
N(S_prime_3..S_prime_5)         = [94*i-169] * [i]^u,
N(S_prime_6)                    = [i]^u,
N(S_prime_7..S_prime_10)        = [-94*i-169] * [i]^u,
```

with an uncomputed unit bit `u` in each column. Unit-generator norms are also
only known to be K-units; their `[i]` bits are not supplied. In particular,
the support decomposition does not determine `M_norm`. The torsion column
for `zeta4` is known to be zero because the relative degree is six, but this
does not determine the remaining fifteen columns.

If a complete set of sixteen actual field elements in one exact basis were
stored, both matrices would be computable without inventing vectors: `M_norm`
comes from the relative multiplication determinants, and `M_const` comes
from expressing the supported K-squareclasses generated by
`[i], [1+i], [94*i-169], [-94*i-169]` in the same S-unit squareclass basis.
That conditional implication is not available from the current payload.

## Q2a Lift Status

Q2a gives the local classes in the local basis

```text
[beta_12] = (0,1,1,0),
[beta_r]  = (0,0,1,0).
```

These are coordinates in `H_pi`, not in the sixteen-dimensional global
ambient space. `D_12` and `D_r` are local branch divisors; no global factor or
global tangent-normalized element is supplied. Therefore the current data
prove neither existence nor nonexistence of global S-unit lifts.

A compatible global norm-square lift would require a vector `v` satisfying

```text
M_loc_pi(v) = [beta_12] or [beta_r],
M_norm(v) = 0,
```

modulo the constant rows `M_const`; the ordinary localization preimage drops
the second equation. None of these solveable systems is currently defined by
stored matrices.

## Next Executable Computation

First serialize the sixteen `BERRY_C1_SUNIT_BASIS` field elements in one
explicit common basis, together with the basis multiplication/reduction data
and the `K` embedding. Then a pure-Python exact computation can derive
`M_const`, `M_norm`, and the four-component localization columns at `pi`, and
solve the two displayed local-preimage systems. Until that computation is
done, no global lift claim is permitted.

This audit does not modify `wl587`-`wl596`, create `wl597`, process another
Berry sextic, or claim a Selmer, rank, or final classification result.

## Q2b Resolution

The missing payload identified above is now supplied by
`q2b-fixed-basis-payload.json`, with the successful public transcript in
`q2b-fixed-basis-magma-result.json`. The payload stores the sixteen actual
`BERRY_C1_SUNIT_BASIS` vectors in the common absolute power basis
`[1,a,...,a^11]`, the defining-polynomial reduction rule, the complete basis
product table, multiplication by `a`, and the selected embedding
`i=-zeta4`, `theta=a`. Exact parser and reuse checks are in
`scripts/theory/berry_sextic_q2b_fixed_basis.py` and
`tests/test_berry_sextic_q2b_fixed_basis.py`.

This resolves the coordinate-data boundary only. It does not compute
`M_const`, `M_norm`, `M_loc_pi`, either global Q2a lift, Selmer data, rank data,
or Q3. A fresh calculator submission was transport-failed in the current
environment; the exact result and rerun command are recorded in
`q2b-fixed-basis-report.md`.
